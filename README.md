# رصد (Rasad) — سکوی چندعاملی پایش خبر ۲۴/۷ · نسخه ۰٫۵ (تحلیل مستند و عملیاتی: RBAC، مرکز هشدار، کاوش پیشرفته، اعلان و خلاصه روزانه، گراف WebGL)

رصد ۱۳ عامل تخصصی را زیر نظر یک «ناظر» (Supervisor) اجرا می‌کند. هر چرخه خبرهای فارسی، عربی و انگلیسی را از ۲۵ منبع واقعی جمع می‌کند، متن کامل را استخراج و نرمال می‌کند، خبرها را دسته‌بندی، خوشه‌بندی و راستی‌آزمایی می‌کند و در پایان بریف فارسی با ارجاع می‌سازد. همه این مراحل در یک رابط فارسی راست‌به‌چپ به‌صورت زنده نمایش داده می‌شوند.

## تحلیل مستند نسخه ۰٫۵

مسیر جدید **تحلیل مستند و شواهد** (`#/analysis`) شامل نسخه ثابت سند، قطعه‌بندی، استخراج ادعا با نقل‌قول دقیق، مقایسه چندمنبعی، نگارش فارسی، کنترل کیفیت، صف پایدار و تأیید انسانی پیش از انتشار است. متن/فایل خصوصی، PDF متنی اختیاری و رونویسی تصویر/صوت API با فعال‌سازی صریح پشتیبانی می‌شود. همه مدل‌ها از API واقعی قابل تنظیم استفاده می‌کنند؛ کلید یا تضمین صحت از پیش فراهم نیست.

**وجود نقل‌قول ≠ صحت خارجی خبر.** استقلال منابع و حقیقت جهان واقعی در این نسخه خودکار اثبات نمی‌شوند. تحلیل سریع و بریف قدیمی همچنان مسیر متفاوت و کم‌ضمانت‌تری دارند. همه پیشنهادهای معماری اولیه در این تغییر تکمیل نشده‌اند.

راهنمای کامل راه‌اندازی، API، محدودیت‌ها و موارد تکمیل‌نشده: [تحلیل مستند](docs/evidence-analysis.md) · [برنامه ارزیابی واقعی](docs/evaluation-plan.md).

## تکمیل گردش بررسی و شواهد

نسخه‌بندی گزارش با ابطال تأیید قبلی، بازاعتبارسنجی، ارجاع به بازبین دیگر و سیاست اختیاری منع خودتأییدی، ذخیره نتایج موفق مراحل، ورود صریح URLهای HTTPS از دامنه‌های مجاز و ثبت روابط منشأ انسانی به مسیر تحلیل مستند افزوده شده‌اند. دریافت سند یا تطابق متن، صحت خبر یا استقلال منبع را ثابت نمی‌کند. [راه‌اندازی و محدودیت‌های این بخش](docs/verification-review-workflows.md).

## اجرای سریع
```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # اختیاری
python -m rasad serve --port 8080   # → http://localhost:8080
# یا فقط یک چرخه از خط فرمان:
python -m rasad run-once
```
- Docker: `docker compose -f deploy/docker-compose.yml up -d --build` (با `--profile llm`، Ollama هم بالا می‌آید)
- systemd: `deploy/rasad.service`
- تست‌ها: `pip install -r requirements-dev.txt && make test`

## سطوح اجرا (Autopilot)
| سطح | رفتار |
|---|---|
| دستی (manual) | زمان‌بند خاموش است و هر مرحله پیش از اجرا تأیید شما را می‌خواهد. |
| نظارتی (supervised) | زمان‌بند هر `RASAD_INTERVAL` ثانیه یک بار اجرا می‌شود و فقط در دروازه‌های `RASAD_GATES` منتظر تأیید می‌ماند: انتشار بریف (با امکان ویرایش متن) و هشدارهای بحرانی. |
| خودکار کامل (autopilot) | همه مراحل بدون توقف اجرا می‌شوند و تصمیم‌ها با عنوان autopilot در ممیزی ثبت می‌شوند. |

کنترل‌های موجود: اجرای چرخه، مکث/ادامه، تحویل کنترل به انسان، کلید توقف اضطراری (فعال‌سازی دوباره فقط با تایپ `ARM`)، اجرای مجدد یک عامل، تأیید/رد/رد شدن از مرحله، و تغییر فاصله زمان‌بند. همه اقدام‌ها در `audit_log` ثبت می‌شوند. اگر سرور وسط اجرا قطع شود، آن اجرا هنگام راه‌اندازی بعدی «قطع» علامت می‌خورد.

## عامل‌ها (به ترتیب خط لوله)
`scout` کاشف منابع · `ingestion` تجمیع‌گر RSS/GDELT با ETag و قرنطینه · `extractor` استخراج متن کامل با trafilatura و رعایت robots.txt · `classifier` طبقه‌بندی ۷ حوزه، فوریت و احساس · `entities` موجودیت‌ها و روابط چندزبانه با مختصات · `dedup` حذف تکرار با MinHash-LSH و خوشه‌بندی بین‌زبانی · `translator` (نیازمند LLM) · `storyline` خط داستان و تکذیب‌ها · `anomaly` جهش حجم و بازیگر نوظهور ⛨ · `verifier` تطبیق منابع مستقل بر اساس گروه مالکیت · `writer` بریف با برچسب «واقعیت مستند / استنباط / فرض» ⛨ · `viz` صحنه‌های حالت نمایش · `qa` شاخص‌های کیفیت.

## نماهای رابط کاربری
اتاق فرمان · کره سه‌بعدی و نقشه تخت · گراف دانش WebGL (sigma.js) و مسیریاب · فهرست‌های پایش · مدیریت سامانه · خط زمانی داستان (تأخیر پوشش، ادعاها، نسخه‌ها) · رودخانه موضوعی و نقشه حرارتی · مقایسه پوشش منابع و تأیید منابع جدید · خط لوله زنده عامل‌ها (ذرات متحرک، بازرس مرحله، پنل تأیید، بازپخش) · بریف‌ها با خروجی MD/PDF · کیفیت و ممیزی · پالت فرمان (Ctrl+K) · حالت نمایش روایی. همه کتابخانه‌ها و فونت‌ها در `web/vendor` قرار دارند و رابط به CDN نیازی ندارد.

## افزودن منبع
از **مدیریت سامانه ← منابع خبری**: آدرس فید را وارد کنید و «اعتبارسنجی فید» را بزنید (فید واقعاً دریافت و مدخل‌هایش شمرده می‌شود). منبع ذخیره‌شده به‌طور پیش‌فرض «در انتظار تأیید» می‌ماند، مگر اینکه گزینه فعال‌سازی فوری را بزنید. ویرایش، غیرفعال‌سازی، حذف (منبعی که خبر ثبت‌شده دارد فقط غیرفعال می‌شود) و ورود/خروج **OPML** هم پشتیبانی می‌شود. روش قدیمی (`sources.yaml` با `status: pending`) همچنان کار می‌کند.

## امکانات نسخه ۰٫۴
### مرکز هشدارها (`#/alerts`)
- هر هشدار این چرخه را طی می‌کند: **جدید ← دیده‌شده ← در حال بررسی ← حل‌شده / کاذب**. هشدار بسته‌شده را می‌توان دوباره باز کرد.
- می‌توانید هشدار را به یکی از کاربران واگذار کنید، یادداشت تحلیلگر بنویسید و تاریخچه کامل اقدام‌ها را با نام کاربر ببینید (جدول `signal_events` و ممیزی).
- فیلتر بر اساس وضعیت، شدت، نوع، مسئول («واگذارشده به من»)، بازه و متن ممکن است. اقدام گروهی و میان‌برهای صفحه‌کلید هم وجود دارد: `J`/`K` برای جابه‌جایی، `A` دیده شد، `R` حل شد، `D` کاذب.
- پنل جزئیات توضیح آماری یا مدل، فرضیه‌های جایگزین و داستان‌های مرتبط را نشان می‌دهد. هشدارهای جهش بازیگر حالا به داستان‌هایشان پیوند دارند.
- **زنگوله اعلان** در نوار بالا شمار هشدارهای باز را نشان می‌دهد؛ اگر هشدار بحرانی باز باشد، با رنگ قرمز چشمک می‌زند. فهرست با رویدادهای زنده به‌روز می‌شود.

### کاوش و جست‌وجوی پیشرفته (`#/explore`)
جست‌وجوی تمام‌متن FTS5 با رتبه‌بندی BM25 و تکه‌متن برجسته‌شده انجام می‌شود. فیلترهای چندگزینه‌ای زبان، موضوع و منبع شمارش زنده دارند. نمودار توزیع زمانی، صفحه‌بندی، مرتب‌سازی (مرتبط‌ترین یا جدیدترین) و خروجی CSV نتایج (تا ۵۰۰۰ ردیف) هم وجود دارد. از پالت فرمان هم می‌توان مستقیم به کاوش رفت. API: `/api/explore` و `/api/explore.csv`.

### توکن‌های API شخصی
از منوی کاربر، بخش «توکن‌های API»، توکن `rsd_…` با مدت اعتبار انتخابی بسازید. توکن فقط یک بار نمایش داده می‌شود و در پایگاه داده فقط هش آن ذخیره می‌شود. از آن با هدر `Authorization: Bearer` استفاده کنید؛ سطح دسترسی آن همان نقش کاربر است. آخرین زمان استفاده ثبت می‌شود و توکن را می‌توان باطل کرد. تغییر رمز یا حذف کاربر همه توکن‌هایش را باطل می‌کند.

### خلاصه روزانه زمان‌بندی‌شده
از **مدیریت ← کانال‌های اعلان** ساعت ارسال را بر اساس منطقه زمانی `RASAD_TZ` (پیش‌فرض Asia/Tehran)، بازه پوشش و تعداد داستان برتر را تعیین کنید. خلاصه شامل آمار، داستان‌های برتر و هشدارهای مهم است. روزی یک بار، صرف‌نظر از سطح اجرا، به کانال‌هایی که «ارسال بریف» دارند فرستاده می‌شود. پیش‌نمایش و «ارسال اکنون» هم وجود دارد.

### رابط واکنش‌گرا
روی موبایل و تبلت، نوار ناوبری به پایین صفحه منتقل می‌شود، شبکه‌ها تک‌ستونه می‌شوند و پنل کناری زیر محتوا قرار می‌گیرد.

## امکانات عملیاتی نسخه ۰٫۳
### کاربران و نقش‌ها (RBAC)
- احراز هویت به‌طور پیش‌فرض فعال است (`RASAD_AUTH=1`). در اولین بازدید، صفحه **راه‌اندازی اولیه** حساب مدیر را می‌سازد. می‌توانید مدیر را از قبل با `RASAD_ADMIN_USER` و `RASAD_ADMIN_PASSWORD` هم بسازید.
- سه نقش وجود دارد: **بیننده** (مشاهده و پرسش از دستیار)، **تحلیلگر** (به‌علاوه تأیید یا رد دروازه‌ها، ویرایش بریف و فهرست‌های پایش) و **مدیر** (به‌علاوه کنترل اجرا، منابع، کاربران، کانال‌ها، تنظیمات مدل، پشتیبان و ممیزی).
- رمزها با PBKDF2-SHA256 و ۲۰۰ هزار تکرار ذخیره می‌شوند. نشست در کوکی HttpOnly/SameSite با عمر ۱۴ روز نگه داشته می‌شود. پس از ۵ تلاش ناموفق در ۵ دقیقه، ورود موقتاً قفل می‌شود. تعلیق یا تغییر رمز همه نشست‌های کاربر را می‌بندد. پشت HTTPS مقدار `RASAD_COOKIE_SECURE=1` را بگذارید.
- همه نقطه‌های پایانی API در میان‌افزار ASGI بر اساس نقش کنترل می‌شوند و پاسخ‌های ۴۰۱ و ۴۰۳ پیام فارسی دارند. رابط کاربری کنترل‌های غیرمجاز را پنهان می‌کند. هدر قدیمی `X-Admin-Token` هم برای اسکریپت‌ها کار می‌کند.

### کانال‌های اعلان
تلگرام (Bot API)، وب‌هوک JSON سازگار با Slack و Mattermost، و ایمیل SMTP پشتیبانی می‌شوند. برای هر کانال حداقل شدت، نوع سیگنال‌ها و ارسال بریف را تعیین کنید. پس از هر اجرا، سیگنال‌های جدید یا تأییدشده ارسال می‌شوند و بریف‌ها پس از تأیید انسانی می‌روند. هر مورد فقط یک بار به هر کانال ارسال می‌شود. دکمه «ارسال آزمایشی» و تاریخچه ارسال هم وجود دارد. اسرار کانال (توکن، رمز و URL) فقط‌نوشتنی هستند و در API پوشانده می‌شوند.

### فهرست‌های پایش (`#/watch`)
تحلیلگر واژه‌های چندزبانه، موجودیت‌ها، موضوع‌ها و زبان‌ها را تعریف می‌کند و آستانه «حداقل خبر در ۶ ساعت» و شدت را تعیین می‌کند. هر انطباق تازه یک سیگنال `watch` با توضیح می‌سازد و از کانال‌های اعلان ارسال می‌شود. خبرهای منطبق ۴۸ ساعت اخیر هم در همین نما دیده می‌شوند.

### گراف دانش حرفه‌ای (sigma.js + graphology، WebGL)
- چیدمان ForceAtlas2 با کاهش اثر گره‌های پرارتباط و حذف هم‌پوشانی (noverlap). دکمه «چیدمان زنده» از Web Worker استفاده می‌کند.
- تشخیص جامعه با Louvain، و محاسبه PageRank، میانجی‌گری (betweenness) و درجه. اندازه و رنگ گره بر اساس هر یک از این شاخص‌ها قابل تنظیم است.
- با گذاشتن نشانگر روی یک گره، همسایه‌هایش برجسته می‌شوند. جست‌وجوی زنده با حرکت دوربین، فیلتر نوع موجودیت از راهنما، آستانه وزن، نمایش «فقط روابط نوع‌دار» و جابه‌جا کردن گره‌ها با کشیدن هم وجود دارد.
- پنل گره شامل رتبه‌ها، جامعه، روابط جهت‌دار و داستان‌های مرتبط است. پنل لبه نقل‌قول‌ها و خبرهای شاهد را نشان می‌دهد.
- مسیریاب کوتاه‌ترین مسیر را سمت کاربر پیدا می‌کند و اگر مسیر از نمای فعلی بیرون باشد، از گراف کامل سرور کمک می‌گیرد.
- خروجی PNG و GEXF (برای Gephi) گرفته می‌شود. تم تیره و روشن پشتیبانی می‌شود و نمای کامل گراف بدون CDN کار می‌کند.

### نگهداری و پایش
- **پشتیبان:** هر ۲۴ ساعت یک پشتیبان آنلاین SQLite با backup API و بدون توقف گرفته می‌شود و فقط `RASAD_BACKUP_KEEP` نسخه آخر نگه داشته می‌شود. پشتیبان‌گیری دستی و دانلود از بخش «سامانه» ممکن است.
- **نگهداری داده:** داده‌های قدیمی‌تر از `RASAD_RETENTION_DAYS` (قابل تغییر در رابط) پاک می‌شوند و checkpoint برای WAL اجرا می‌شود.
- **پایش:** `/metrics` متریک‌ها را با قالب Prometheus می‌دهد و `/healthz` برای بررسی سلامت است.
- **خروجی‌ها:** CSV داستان‌ها و خبرها (سازگار با Excel)، GEXF گراف و OPML منابع.
- **ممیزی:** نمای «ردپای ممیزی» با فیلتر بر اساس کاربر و کنش.

## هوش مصنوعی (یکپارچه در همه عامل‌ها)
اتصال از طریق هر endpoint سازگار با OpenAI برقرار می‌شود. پیش‌فرض این استقرار: `https://vyceai.com/v1` با مدل `gpt-6-luna` و مدل جایگزین `deepseek-v4-flash`. کلید در فایل `.env` (با مجوز 600 و خارج از git و بسته خروجی) یا از صفحه **تنظیمات هوش مصنوعی** قرار می‌گیرد. کلید فقط نوشتنی است و هرگز به مرورگر برگردانده نمی‌شود.

| عامل | کاربرد مدل زبانی |
|---|---|
| کاشف منابع | پروفایل منبع کاندید: مالکیت، گرایش، اعتبار پیشنهادی و ریسک (تصمیم نهایی با انسان) |
| طبقه‌بند | طبقه‌بندی صفر-نمونه خبرهای بدون برچسب یا مبهم، و بازبینی فوریت و احساس |
| موجودیت و رابطه | کشف افراد، سازمان‌ها و رویدادهای خارج از فهرست مرجع، و روابط نوع‌دار (تحریم، حمله، مذاکره…) با نقل‌قول شاهد |
| حذف تکرار | داوری ادغام داستان‌های بین‌زبانی هم‌رویداد (فقط با اطمینان ≥ ۰٫۸) |
| مترجم | عنوان فارسی، تیتر بی‌طرف و خلاصه دوجمله‌ای داستان‌ها، و ترجمه عنوان خبرها (دسته‌ای و موازی) |
| خط داستان | روایت تحول، فاز (نوظهور / تشدید / ثبات / کاهش / پایان) و نشانگر پایش |
| الگو و ناهنجاری | علت محتمل سیگنال، دو فرضیه جایگزین و نشانگر تأیید یا رد |
| راستی‌آزما | استخراج ادعا با شماره منبع پشتیبان یا متناقض، و مقایسه قاب‌بندی رسانه‌ها. «مستند» فقط وقتی پذیرفته می‌شود که دو گروه مالکیت مستقل منبع آن باشند |
| تحلیلگر نویسنده | BLUF، خلاصه مدیریتی، تحلیل، داوری‌های کلیدی و چشم‌انداز. جمله‌های بدون ارجاع معتبر حذف می‌شوند |
| کارگردان بصری | روایت صحنه‌های حالت نمایش |
| ارزیاب کیفیت | داوری وفاداری بریف به منابع (LLM-as-judge) |

قابلیت‌های تعاملی:
- **دستیار تحلیلی** (`#/ask`): بازیابی ترکیبی (FTS5 + پیوند موجودیت) از پایگاه رصد، پاسخ استریم‌شده با ارجاع قابل‌کلیک و برچسب شواهد
- **تحلیل عمیق داستان**: بازیگران، ادعاها، قاب‌بندی، پیامدها، سناریوها و پرسش‌های باز
- **بریف سفارشی** بر اساس موضوع، بازیگر یا مکان و بازه زمانی
- **ترجمه متن خبر** در لحظه

دروازه هوش مصنوعی (`rasad/llm.py`) این امکانات را دارد: تلاش مجدد با عقب‌نشینی نمایی، مدل جایگزین، سقف توکن روزانه، کلید فعال/غیرفعال برای هر عامل، ثبت هر فراخوانی در جدول `llm_calls` (توکن، تأخیر، خطا)، محافظ تزریق دستور با `<untrusted_content>` و تعمیر خودکار JSON نامعتبر. API‌های مرتبط: `/api/ai/config`، `/api/ai/test`، `/api/ai/models`، `/api/ai/usage`، `/api/ask`، `/api/stories/{id}/analyze`، `/api/briefs/custom` و `/api/articles/{id}/translate`.

**هزینه:** فراهم‌کننده فعلی به هر درخواست حدود ۴٬۴۰۰ توکن سربار اضافه می‌کند. به همین دلیل همه کارها دسته‌ای انجام می‌شوند و فقط داستان‌هایی دوباره پردازش می‌شوند که خبر تازه گرفته‌اند. اولین اجرا با بک‌لاگ حدود ۱۲۰ هزار توکن مصرف کرد و اجراهای بعدی معمولاً کمتر مصرف می‌کنند. سقف روزانه پیش‌فرض ۳ میلیون توکن است.

## نگاشت MVP به معماری هدف (v1)
| MVP فعلی | معماری هدف |
|---|---|
| SQLite (WAL) + FTS5 | PostgreSQL + pgvector + TimescaleDB، OpenSearch |
| گذرگاه رویداد درون‌فرآیندی + SSE | NATS JetStream |
| Supervisor با asyncio | Temporal (دوام اجرا) + LangGraph (interrupt برای تأیید) |
| فهرست مرجع موجودیت‌ها + قواعد | GLiNER / ParsBERT-NER، Hazm، bge-m3 |
| روابط هم‌آیندی در SQLite | Neo4j + Graphiti (گراف زمانی) |
| ~~گراف ECharts~~ → **sigma.js / graphology (انجام شد در v0.3)** | sigma.js / graphology |
| LLM اختیاری | LiteLLM (مسیریابی، بودجه، fallback) |
| RBAC داخلی (SQLite) | SSO/OIDC (Keycloak) |
| اعلان تلگرام/وب‌هوک/ایمیل | Alertmanager / صف اعلان |

## محدودیت‌های فعلی
- اگر کلید یا اعتبار حساب هوش مصنوعی تمام شود، عامل‌ها به حالت قطعی (بدون مدل زبانی) برمی‌گردند. در این حالت ترجمه انجام نمی‌شود.
- خوشه‌بندی بین‌زبانی بر اساس موجودیت‌های مشترک و زمان، به‌علاوه داوری مدل زبانی است. فراهم‌کننده فعلی endpoint برای embedding ندارد.
- فایل‌های Docker و systemd نوشته شده‌اند، اما در محیط توسعه اجرا و آزمایش نشده‌اند.
- احراز هویت داخلی است (کاربر/رمز). ورود یکپارچه SSO/OIDC و احراز دومرحله‌ای هنوز پیاده نشده‌اند.
- در گراف‌های خیلی بزرگ (بیش از ۹۰۰ گره)، محاسبه میانجی‌گری در مرورگر غیرفعال می‌شود.
