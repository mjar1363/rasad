# تحلیل مستند محتوا — راهنمای نسخه ۰٫۵

این مسیر یک پیاده‌سازی جدید و جدا از تحلیل سریع قدیمی است؛ `#/analysis` و دکمه «تحلیل مستند و دفتر شواهد» در صفحه داستان به همان صف متصل‌اند. هیچ خروجی قدیمی به‌صورت خودکار «راستی‌آزمایی‌شده» ارتقا داده نمی‌شود.

## آنچه واقعاً پیاده شده است

- نسخه ثابت سند با SHA-256 شامل متن، انتساب، زمان و روش استخراج؛ تغییر متن/فراداده نسخه تازه می‌سازد.
- قطعه‌های حداکثر ۲۲۰۰ نویسه با ۱۸۰ نویسه هم‌پوشانی؛ گزارش تعداد قطعه‌ها و پوشش **نویسه‌های یکتا**، بدون نمایش پردازش جزئی به‌عنوان پوشش کامل.
- دریافت متن کامل خبر در اولویت؛ اگر فقط چکیده در دسترس است، محدودیت در فراداده ثبت می‌شود. زمان انتشار از زمان رویداد جداست.
- بازیابی واژگانی و embedding ترکیبی اختیاری با مدل و کلید مستقل؛ نبود نتیجه مرتبط باعث پاسخ صریح «شواهد کافی نیست» می‌شود. fallback به خبر نامرتبط حذف شده است.
- استخراج ادعای اتمی، گوینده/زمان نامعلوم nullable، مشاهدات موجودیت، رویداد، عدد، قاب‌بندی و اختلاف تیتر/متن با شاهد.
- اعتبارسنجی محلی Pydantic اجباری؛ `json_schema` فقط در صورت فعال‌سازی مدیر برای endpoint سازگار. خروجی ناقص/refusal رد می‌شود؛ fallback خاموش و پنهانی از schema سخت‌گیرانه نداریم.
- تطبیق عین نقل‌قول با نسخه سند و محاسبه offset سمت سرور. نقل‌قول مفقود، مبهم، شناسه خارج از مجموعه مجاز یا ادعای بی‌شاهد ثبت نمی‌شود.
- ارزیابی محدود و چندمنبعی رابطه ادعا/شاهد: پشتیبانی، تعارض محتمل، منشأ مشترک احتمالی، زمان متفاوت، مرتبط و ناکافی. این‌ها **داوری مدل** هستند، نه اثبات استقلال یا صحت خارجی.
- نگارش ساخت‌یافته در هشت حالت: خبر، مقایسه، خط زمانی، قاب‌بندی، پیامد، سناریو، بریف، پرسش. استنباط به فرض و سناریو به فرض + نشانگر پایش نیاز دارد؛ احتمال عددی تولید نمی‌شود.
- کنترل ساختاری و داوری جداگانه مدل برای همه جملات `reported`؛ بررسی قیود/اعداد/زمان/انتساب. رد یا ابهام داور، انتشار را مسدود می‌کند. داوری می‌تواند خطا کند؛ تأیید انسانی همچنان اجباری است.
- دفتر ادعا و شواهد، محل دقیق نقل‌قول، محدودیت‌ها، دامنه انتخاب، provenance مدل/endpoint/prompt/hash، مصرف توکن و تاریخچه تصمیم بازبین در رابط فارسی.
- صف پایدار SQLite، lease، checkpoint قطعه‌های استخراج‌شده، بازیابی پس از قطع، لغو در نقطه امن، تلاش مجدد دستی و توقف اضطراری. مراحل تطبیق/نگارش ممکن است پس از قطع دوباره هزینه ایجاد کنند؛ فقط استخراج checkpoint قطعه‌ای دارد.
- اسناد واردشده، کارها و گزارش‌ها خصوصی به مالک و مدیر؛ دسترسی هر درخواست دوباره کنترل می‌شود. نقش تحلیلگر برای ایجاد/تأیید/انتشار لازم است؛ بیننده فقط داده مجاز خود را می‌خواند.
- حداکثر ۵ کار فعال/کاربر، ۱۲ سند، ۶۰ قطعه/کار، ۱۲ ادعا و ۱۲ مشاهده/بسته استخراج، ۴۰ ادعا برای تطبیق و نگارش، ۱۶ جمله نهایی. سقف‌ها و موارد حذف‌شده در manifest/QA دیده می‌شوند. این نسخه برای تحلیل بی‌کران کل آرشیو نیست.

## معنای اعتبار

۱. **اعتبار مکانیکی شاهد:** نقل‌قول واقعاً در آن نسخه سند وجود دارد؛ سرور بررسی می‌کند.

۲. **وفاداری معنایی:** آیا شاهد واقعاً ادعا/جمله را با همه قیود پشتیبانی می‌کند؟ مدل ارزیابی می‌کند؛ بازبین باید بررسی کند.

۳. **صحت خارجی/استقلال:** آیا رویداد در جهان رخ داده و منابع واقعاً مستقل‌اند؟ این نسخه آن را خودکار اثبات نمی‌کند؛ `external_verification=false` و `source_independence=not_established` عمداً ثبت می‌شوند. چند URL، چند نقل‌قول یا مالک متفاوت کافی نیست. هیچ امتیاز اعتباری عددی مصنوعی یا تضمین صحت ۱۰۰٪ وجود ندارد.

## راه‌اندازی

```bash
pip install -r requirements.txt
# فقط برای PDF متنی:
pip install -r requirements-media.txt
python -m rasad serve --host 127.0.0.1 --port 8080
```

از تنظیمات مدیر یک endpoint واقعی OpenAI-compatible، **شناسه مدل واقعاً موجود در حساب** و کلید API وارد کنید. ابتدا آزمون اتصال را بزنید. آزمون ساده اتصال، پشتیبانی schema، embedding، تصویر و صوت را تضمین نمی‌کند؛ هر کدام باید جداگانه آزموده شوند. مخزن هیچ کلید، اعتبار رایگان یا مدل خیالی فراهم نمی‌کند. نمونه محلی `qwen3:8b` فقط زمانی کار می‌کند که همان مدل روی endpoint شما نصب باشد.

`structured_outputs` را در تنظیمات هوش مصنوعی تنها پس از تأیید پشتیبانی `response_format.json_schema` برای مدل اصلی **و جایگزین** فعال کنید. در حالت خاموش، JSON mode + اعتبارسنجی محلی استفاده می‌شود، نه تضمین schema در سمت فراهم‌کننده.

### embedding

```dotenv
EMBED_BASE_URL=https://YOUR-ENDPOINT/v1
EMBED_API_KEY=YOUR_SEPARATE_SECRET
EMBED_MODEL=YOUR_AVAILABLE_MULTILINGUAL_MODEL
RASAD_EMBEDDING_DAILY_REQUESTS=100
```

API `/embeddings`، ترتیب index و ابعاد/اعداد متناهی بردار بررسی می‌شوند. کش به endpoint/model/chunk وابسته است. RRF واژگانی/کسینوسی برای مرتبط‌بودن است، نه احتمال صحت. آستانه ۰٫۳۵ یک پیش‌فرض تنظیم مهندسی است و باید روی پیکره واقعی ارزیابی شود. embedding روی تمام قطعه‌های اسناد انتخابی محاسبه می‌شود؛ برای سند بسیار بلند هزینه پیش از برش max_chunks هم ایجاد می‌شود.

### فایل و رسانه

- TXT: UTF-8 محلی، حداکثر ۲۰۰هزار نویسه.
- PDF: متن بومی، حداکثر ۱۰۰ صفحه، شماره صفحه و بازه نویسه. PDF رمزدار/اسکن فاقد متن رد می‌شود؛ OCR خودکار PDF اسکن‌شده پیاده نشده است.
- PNG/JPEG/WebP: با `RASAD_MEDIA_API=1` و مدل بینایی سازگار، متن رونویسی می‌شود. **اصالت تصویر، دست‌کاری تصویر یا کادر هندسی متن ارزیابی نمی‌شود.**
- MP3/WAV/MP4/WebM: با همان opt-in، endpoint `/audio/transcriptions` و قرارداد `verbose_json`؛ مدل `RASAD_TRANSCRIPTION_MODEL` باید این قرارداد را پشتیبانی کند (پیش‌فرض `whisper-1`). timestamp فقط اگر فراهم‌کننده segment بدهد؛ در غیر این صورت محل فقط بازه متن است. هویت گوینده تضمین نیست.
- ویدئو در این نسخه صرفاً ورودی رونویسی صوت است؛ تحلیل فریم، چهره، صحنه و همگام‌سازی صوت/تصویر نداریم.
- سقف فایل ۸ MiB؛ فایل اصلی خارج از webroot با مجوز محدود نگهداری و فقط با کنترل مالکیت قابل دانلود است. این یک sandbox ضدبدافزار/محدودکننده CPU برای PDF نیست؛ ورودی خصمانه را در استقرار عمومی با اسکنر و محیط استخراج ایزوله محدود کنید.
- رونویسی ماشینی به‌عنوان `machine_transcription_unverified` علامت می‌خورد. تطبیق نقل‌قول با رونویسی، صحت آن در فایل اصلی را ثابت نمی‌کند. بازبین باید فایل را بررسی کند.

## گردش انتشار

`queued → extracting → assessing → synthesizing → validating → needs_review`

گزارش: `draft → approved → published` یا `draft → rejected`.

حتی در autopilot هیچ فراخوانی خودکار به تأیید/انتشار مسیر جدید وجود ندارد. بازبین باید یادداشت بدهد. انتشار جدید فقط وضعیت درون‌سامانه‌ای است و به Telegram/webhook/email ارسال نمی‌کند. نویسنده/QA قدیمی هنوز مسیر قدیمی‌اند و برچسب هشدار دارند؛ دروازه آن‌ها نباید به‌عنوان ضمانت مسیر جدید معرفی شود. تأیید توسط خود مالک مجاز است؛ الزام «بازبین دوم مستقل» در این نسخه وجود ندارد.

## API

احراز هویت و RBAC فعلی برنامه برقرار است (کوکی یا Bearer شخصی؛ `X-Admin-Token` فقط مدیر).

| روش/مسیر با پیشوند `/api/analysis` | کارکرد |
|---|---|
| GET `/capabilities` | پیکربندی قابلیت‌ها، نه گواه آزموده‌شدن |
| POST `/documents` | `{title,text,language?}` ورود متن خصوصی |
| POST `/documents/upload?title=...` | بایت خام فایل با Content-Type صحیح؛ multipart فرم نیست |
| GET `/documents/{id}` | نسخه سند و قطعه‌ها |
| GET `/documents/{id}/original` | فایل اصلی واردشده، دانلود امن |
| GET `/chunks/{id}` | متن قطعه و locator |
| DELETE `/documents/{id}` | حذف سند غیرمرجع و کش embedding/فایل اصلی |
| POST `/jobs` | ایجاد کار با `article_ids`, `story_id`, `document_ids`, `question`, `mode`, `hours`, `max_chunks` |
| GET `/jobs` | ۳۰ کار اخیر خود کاربر؛ سقف limit=100 |
| GET `/jobs/{id}` | وضعیت، پیشرفت، manifest و report_id |
| POST `/jobs/{id}/cancel` | درخواست لغو؛ فراخوانی API جاری فوراً قطع نمی‌شود |
| POST `/jobs/{id}/retry` | فقط failed/cancelled، با استفاده از checkpoint |
| DELETE `/jobs/{id}` | حذف کار نهایی و گزارش/ادعا/شاهد/ردیابی وابسته |
| GET `/jobs/{id}/claims` | دفتر ادعا و نقل‌قول‌ها |
| GET `/reports/{id}` | گزارش/QA/تصمیم‌ها/ردیابی مدل |
| POST `/reports/{id}/review` | `{decision:"approve"|"reject",note,revision:1}` |
| POST `/reports/{id}/publish` | فقط approved و QA قبول و توقف اضطراری خاموش |

خطای کنترل schema درخواست: 422؛ نبود/عدم مجوز مشاهده شیء: 404؛ وضعیت متعارض حذف/تلاش مجدد: 409؛ خطای دامنه/اعتبار: 400. OpenAPI در `/docs` قراردادها را نمایش می‌دهد.

## مصرف، پایداری و امنیت

- توکن گفتگو: رزرو اتمی محافظه‌کارانه برای تلاش‌ها، ثبت استفاده واقعی در `llm_calls`، RPM و semaphore مشترک. شمارش token دقیق پیش از درخواست بدون tokenizer و رفتار فراهم‌کننده تضمین نیست. `LLM_TOKEN_OVERHEAD` حاشیه رزرو است؛ reasoning پنهان یا usage مفقود می‌تواند هزینه متفاوت ایجاد کند. تصاویر به علت برآورد محافظه‌کارانه بایتی ممکن است بودجه بیشتری رزرو کنند.
- embedding/رونویسی: **سقف جداگانه تعداد درخواست** با `RASAD_EMBEDDING_DAILY_REQUESTS` و `RASAD_TRANSCRIPTION_DAILY_REQUESTS`، شمارش تلاش حتی در خطا، همان RPM/concurrency و دفتر `analysis_aux_calls`. مصرف ثانیه/توکن/دلار این APIها در سقف توکن گفتگو ادغام نشده؛ قیمت‌گذاری ساختگی تولید نمی‌شود.
- در پنل فراهم‌کننده حتماً سقف مالی و هشدار هزینه بگذارید. سیستم حسابداری مالی سخت‌گیرانه یا تضمین حداکثر صورتحساب نیست.
- محتوای منبع در user message و پوشش داده نامطمئن قرار دارد. مدل ابزار مرورگر/اجرا/انتشار ندارد. schema و کنترل شناسه/نقل‌قول لایه دفاعی‌اند؛ prompt injection را کاملاً حل نمی‌کنند.
- SQLite+قفل محلی برای **یک فرایند ASGI** طراحی شده؛ با چند worker یا چند میزبان بدون مهاجرت صف به Postgres/Redis اجرا نکنید. lease ۳۰ دقیقه است؛ توقف در وسط request ممکن است مصرف مدل را لغو نکند. worker این مسیر در `serve` اجرا می‌شود، نه CLI قدیمی `run-once`.
- DB snapshot شامل نسخه‌ها و شواهد است، اما فایل‌های اصلی پوشه `analysis-media` را هم در پشتیبان volume جدا نگه دارید؛ پشتیبان SQLite به‌تنهایی فایل‌های اصلی را ندارد. نسخه‌های سند به retention خودکار خبرها متصل نیستند تا ارجاع گزارش‌ها شکسته نشود. حذف صریح API برای نگهداری/حریم خصوصی موجود است؛ فایل‌ها و نسخه‌های پشتیبان نیز باید طبق سیاست حذف شما رسیدگی شوند.
- اسناد ممکن است حساس باشند: پیش از فعال‌سازی endpoint خارجی، اقامت داده، قرارداد پردازش داده و رضایت مالکان محتوا را بررسی کنید. اسناد برای ایندکس سراسری/کاربر دیگر منتشر نمی‌شوند.

## آزمون و معیار پذیرش

```bash
pip install -r requirements-dev.txt
pytest -q
for f in web/js/*.js; do node --input-type=module --check < "$f"; done
```

آزمون‌ها با پاسخ‌های مدل **شبیه‌سازی‌شده** قراردادها، offset فارسی، immutability، نقل‌قول جعلی/مبهم، امتناع در نبود شاهد، جلوگیری از انتشار، مالکیت، checkpoint، رزرو بودجه و retry اعلان را بررسی می‌کنند. این قبولی، کیفیت مدل واقعی را اثبات نمی‌کند.

قبل از استقرار عملیاتی، نمونه فارسی/عربی/انگلیسی و موارد جدول `evaluation-plan.md` را با کلید واقعی و پیکربندی نهایی اجرا کنید؛ بازبین انسانی روی شاهد اصلی داوری کند. در این تغییرات هیچ آزمون پولی واقعی یا deploy انجام نشده است.

## خارج از دامنه تکمیل‌شده

راستی‌آزمایی مستقل وب/اسناد اولیه، گراف اثبات منشأ بازنشر، تضمین truth، آموزش/تنظیم مدل، benchmark برچسب‌خورده واقعی، API بومی Anthropic citations، OCR سند اسکن‌شده، تحلیل اصالت تصویر/ویدئو، diarization تضمین‌شده، vector DB مقیاس‌بالا، صف توزیع‌شده، تبدیل تمامی عامل‌های قدیمی به این قرارداد، ارسال خارجی گزارش جدید و همه پیشنهادهای عمومی بازطراحی پروژه هنوز پیاده‌سازی کامل نشده‌اند. این موارد نباید در گزارش انتشار به‌عنوان قابلیت حاضر اعلام شوند.

## اصلاحات همراه مسیر جدید

اولویت متن کامل نسبت به lead، حذف fallback خبر نامرتبط، جداسازی تاریخچه دستیار بر اساس user_id، شناسه fallback پایدار موجودیت، ثبت اتمی مصرف، pacing/concurrency استریم، مخفی‌سازی خطای اعلان و header_value، امکان تلاش دوباره اعلان ناموفق در dispatch بعدی، حذف هشدار pending/dismissed از digest، محدودسازی gate هشدار به شناسه‌های همان مرحله، کنترل شماره ارجاع داوری‌ها و چشم‌انداز بریف قدیمی، مدیریت عمر taskهای startup و مسیر volume پشتیبان Docker اصلاح شده‌اند. تلاش مجدد اعلان یک صف تحویل با backoff یا تضمین exactly-once توزیع‌شده نیست؛ در نبود dispatch بعدی خودکار تکرار نمی‌شود. تاریخچه chat قدیمی که مالک قابل اثبات ندارد (`user_id IS NULL`) به کاربر فعلی نسبت داده نمی‌شود و در فهرست خصوصی نمایش داده نخواهد شد.
