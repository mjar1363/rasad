# تکمیل گردش بازبینی و شواهد بیرونی

این بخش مسیر `/api/analysis` و رابط `#/analysis` را توسعه می‌دهد؛ عامل‌های قدیمی را جایگزین نمی‌کند. «بازاعتبارسنجی» در این سند یعنی کنترل ساختار و وفاداری متن به ادعاهای موجود، نه اثبات حقیقت خبر.

## راه‌اندازی و مهاجرت

نصب و اجرای همان برنامه کافی است؛ `db.init()` جدول‌های افزایشی نسخه ۲ را می‌سازد و داده‌های نسخه ۱ را نگه می‌دارد. پیش از ارتقا از SQLite و پوشه `analysis-media` پشتیبان بگیرید. یک فرایند ASGI اجرا کنید؛ این تغییر صف یا پایگاه داده توزیع‌شده نیست.

```dotenv
RASAD_EXTERNAL_FETCH=0
RASAD_EXTERNAL_ALLOWED_HOSTS=
RASAD_EXTERNAL_DAILY_IMPORTS=10
RASAD_REQUIRE_SECOND_REVIEWER=0
```

برای دریافت URL، گزینه اول را آگاهانه ۱ کنید و نام دقیق دامنه‌های مجاز را با کاما بنویسید؛ برای مثال `example.org,www.example.org`. زیر‌دامنه به‌طور ضمنی مجاز نمی‌شود. دامنه مقصد هر redirect نیز باید صریحاً مجاز باشد. این گزینه مستقل از فعال‌سازی API مدل است. روشن‌کردن آن به برنامه اجازه دریافت سند می‌دهد، نه جست‌وجوی آزاد وب یا ارسال خودکار سند به مدل.

## دریافت امن سند بیرونی

- فقط HTTPS روی پورت ۴۴۳؛ بدون نام کاربری/رمز در URL، کوکی، توکن یا header سفارشی.
- بررسی همه پاسخ‌های DNS و رد IPهای غیرعمومی و multicast؛ اتصال به IP بررسی‌شده با SNI نام میزبان و گواهی TLS معتبر انجام می‌شود. بازحل‌کردن DNS هنگام اتصال و proxy محیطی استفاده نمی‌شود.
- کنترل مجدد دامنه، DNS و robots در هر hop. حداکثر چهار hop. robots ناموفق به‌جز 404 دریافت را متوقف می‌کند؛ redirect خود robots نیز دنبال نمی‌شود.
- فقط پاسخ ۲۰۰ از نوع HTML/XHTML یا متن ساده، حداکثر ۲ MiB و بدون محتوای فشرده پذیرفته می‌شود. سقف robots برابر ۲۵۶ KiB، مهلت هر پاسخ ۳۰ ثانیه و timeout سوکت ۱۰ ثانیه است. این محدودیت، timeout سراسری همه hopها یا DNS سیستم نیست.
- دو دریافت هم‌زمان در هر فرایند و سقف روزانه تلاش ورود برای هر کاربر؛ هر تلاش ممکن است چند درخواست robots/redirect داشته باشد. شکست نیز سهم تلاش را مصرف می‌کند.
- متن HTML استخراج می‌شود؛ پوشش جزئی است و متن بیش از سقف سند ۲۰۰ هزار نویسه پذیرفته نمی‌شود. فایل خام، SHA-256، URL درخواستی/نهایی، زمان دریافت و نسخه متن خصوصی ثبت می‌شوند. حقوق محتوا، رضایت و اقامت داده همچنان مسئولیت بهره‌بردار است.
- `source_type=primary_claimed` ادعای انسانی درباره اولیه‌بودن است. `origin_verified=false` باقی می‌ماند. hash فقط تمامیت نسخه دریافت‌شده را نشان می‌دهد، نه اصالت ناشر یا صحت روایت.

آزمون‌های دریافت با DNS/transport شبیه‌سازی‌شده اجرا شده‌اند؛ در این تغییر، سایت عمومی واقعی دریافت نشده است.

## روابط منشأ و تحلیل تکمیلی

رابطه‌های `republication`, `cites`, `translation`, `same_origin_claimed` با یادداشت و ثبت‌کننده ذخیره می‌شوند. هر دو سند باید برای ثبت‌کننده مجاز باشند؛ رابطه به خود و چرخه در مجموعه روابط همان ثبت‌کننده رد می‌شود. روابط دیگر کاربران پنهان‌اند، مگر برای مدیر؛ بنابراین کنترل چرخه تضمین سراسری روی داده‌های پنهان نیست.

گروه‌بندی متن کاملاً یکسان با hash انجام می‌شود. شباهت معنایی، منشأ مشترک و استقلال مالکیت از این تطابق نتیجه گرفته نمی‌شوند. manifest گزارش تصویری ثابت از روابط زمان ساخت است؛ افزودن رابطه بعدی، گزارش قبلی را بی‌صدا عوض نمی‌کند.

تحلیل تکمیلی فقط بعد از آماده‌شدن دامنه تحلیل اولیه و با حداقل یک سند تازه ساخته می‌شود. حداکثر شش شناسه تکمیلی و حداکثر دوازده سند در مجموع مجاز است. نتیجه، کار مقایسه‌ای خصوصی تازه برای درخواست‌کننده است؛ گزارش اولیه تغییر نمی‌کند. شناسه کار والد در audit ثبت می‌شود؛ این یک گراف کامل نسخه‌های پژوهش نیست.

## نسخه‌بندی و بازاعتبارسنجی

۱. مالک یا مدیر می‌تواند گزارش draft/approved/rejected را با شماره نسخه مورد انتظار اصلاح کند. نسخه منتشرشده و نسخه درحال اعتبارسنجی قابل ویرایش نیستند.
۲. متن، QA و وضعیت قبلی در تاریخچه می‌ماند؛ نسخه جدید draft و QA ناموفق می‌شود. تأیید قدیمی برای شماره نسخه جدید قابل استفاده نیست.
۳. بازاعتبارسنجی، شناسه ادعاها، الزام شاهد، فرض‌ها و نشانگر سناریو و وفاداری جملات reported را کنترل می‌کند. تغییر عدد یا نقل ادعای دیگر باید توسط داور رد شود؛ توان داور واقعی نیازمند ارزیابی جداگانه است. inference/scenario حکم اثبات‌شده نیستند و بازبین انسانی باید خود آن‌ها را بخواند.
۴. پاسخ ناقص، uncertain، unsupported یا خطا مسیر انتشار را می‌بندد. قبولی QA نیز جای تأیید انسانی همین نسخه را نمی‌گیرد.
۵. برای اجرای هم‌زمان، lease سی‌دقیقه‌ای با token وجود دارد؛ اجرای قدیمی نمی‌تواند نتیجه اجرای جایگزین را بازنویسی کند. اگر فرایند قطع شود، بعد از انقضای lease درخواست دستی بازاعتبارسنجی را تکرار کنید. این عملیات API هم‌زمان است، نه صف پس‌زمینه خودکار.

رابط امکان اصلاح متن و محدودیت‌ها را دارد؛ API قرارداد کامل جملات نوع‌دار را می‌پذیرد. ادعاهای مرجع و فایل‌های اصلی با ویرایش گزارش تغییر نمی‌کنند.

## ارجاع به بازبین دیگر

مالک/مدیر می‌تواند گزارش را به یک تحلیلگر یا مدیر فعال دیگر ارجاع دهد. **این کار دسترسی به متن کامل اسناد منتخب آن تحلیل، قطعه‌ها، گزارش، ردیابی‌ها و تاریخچه را به بازبین می‌دهد.** ارجاع را فقط با رضایت مالک محتوا انجام دهید. بازبین حق اصلاح گزارش، لغو/حذف کار، حذف سند یا انتشار را از ارجاع نمی‌گیرد. می‌تواند نتیجه را با یادداشت تأیید یا رد کند و تحلیل تکمیلی جداگانه از اسناد مجاز بسازد.

لغو ارجاع دسترسی بعدی را قطع می‌کند؛ فایل دریافت‌شده یا تحلیل تکمیلی خصوصی قبلاً ساخته‌شده را از دستگاه/حساب بازبین پس نمی‌گیرد. تأیید تاریخی با لغو ارجاع حذف نمی‌شود.

با `RASAD_REQUIRE_SECOND_REVIEWER=1` مالک و ویرایشگر جاری نمی‌توانند بازبین تأیید/رد باشند. انتشار مجدداً تأیید همین نسخه، متفاوت‌بودن حساب و نقش فعال تأییدکننده را بررسی می‌کند؛ تأیید خودی قدیمی پس از روشن‌کردن سیاست کافی نیست. پیش‌فرض ۰ برای سازگاری قبلی است. در حالت بدون احراز هویت محلی، جدایی هویت واقعی وجود ندارد؛ این سیاست را با حساب‌های واقعی و `RASAD_AUTH=1` به کار ببرید. حساب دیگر به معنی استقلال سازمانی یا سیاسی نیست.

## بازیابی مراحل و هزینه

خروجی موفق و schema-valid هر فراخوانی مرحله در همان کار ذخیره می‌شود. کلید شامل نسخه prompt، system/payload/schema، سقف توکن و تنظیمات مؤثر مدل/endpoint است؛ کلید API در cache ذخیره نمی‌شود. تکرار همان ورودی از نتیجه استفاده می‌کند و مصرف قبلی را دوباره جمع نمی‌زند. ورودی یا تنظیمات متفاوت باعث فراخوانی تازه می‌شود.

پس از دریافت پاسخ، مصرف اعلام‌شده و خروجی معتبر پیش از بررسی لغو ثبت می‌شوند؛ نتیجه schema-invalid مصرفش ثبت می‌شود اما cache نمی‌شود. قطع بعد از صورتحساب فراهم‌کننده و پیش از commit محلی، یا خطای فراهم‌کننده بدون usage، همچنان می‌تواند اختلاف حساب و هزینه تکراری بسازد. تضمین exactly-once یا سقف مالی سخت وجود ندارد؛ سقف مالی حساب فراهم‌کننده ضروری است. ذخیره نتایج نیز داده حساس است و باید همراه پشتیبان‌ها محافظت شود.

## API افزوده‌شده

همه مسیرهای زیر پیشوند `/api/analysis` دارند. قرارداد دقیق، حدود و پاسخ خطا در `/docs` است.

| روش/مسیر | ورودی یا نتیجه |
|---|---|
| POST `/documents/external` | `{url,title,source_type}`؛ نسخه خصوصی `{id}` |
| GET `/provenance?document_ids=id1,id2` | روابط مجاز و گروه متن یکسان |
| POST `/provenance` | `{child_id,parent_id,relation,note}` |
| DELETE `/provenance/{id}` | فقط صاحب رابطه یا مدیر |
| POST `/jobs/{id}/followup` | `{document_ids,question?}`؛ کار تازه |
| GET `/reviewers` | حساب‌های فعال analyst/admin، بدون ایمیل |
| GET `/review-inbox` | گزارش‌های ارجاع‌شده به کاربر جاری |
| POST `/reports/{id}/assignment` | `{reviewer_id}`؛ null برای لغو |
| POST `/reports/{id}/revise` | `{revision,statements,limitations,note}` |
| POST `/reports/{id}/revalidate` | `{revision}`؛ اجرای کنترل کیفیت |
| GET `/reports/{id}/history` | نسخه جاری و نسخه‌های بایگانی‌شده |

## کارهای باقی‌مانده

راستی‌آزمایی مستقل و خودکار وب، تضمین منشأ/استقلال، API بومی citations، OCR سند اسکن‌شده، اصالت‌سنجی تصویر و ویدئو، benchmark واقعی چندزبانه، صف/DB توزیع‌شده، مهاجرت کامل مسیرهای قدیمی و ارسال خارجی گزارش جدید هنوز تکمیل نشده‌اند. این فاز نباید به‌عنوان تکمیل تمام نقشه‌راه معرفی شود.
